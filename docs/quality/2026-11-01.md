# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Python 3.14.5 (fresh `.venv`),
Node.js 24, Windows 11, Intel Core i7-13700H. External calls: the OpenLineage HTTP transport
(Python) and the Marquez REST API (TypeScript); the Marquez, Spark and Airflow runs are CI-only.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | Python: the HTTP transport has a 10 s timeout (`emitter.client_for`); the installed openlineage-python 1.54.0 retries POSTs at most 5 times with backoff 0.3 on 500/502/503/504 (`http_common.DEFAULT_RETRY_CONFIG`) and raises on an HTTP error (`raise_for_status`), so a failed START stops the run instead of being dropped. TypeScript: every request has `AbortSignal.timeout` (10 s default), a body cap (16 MiB) and an item cap (10,000), and every failure becomes a `MarquezError` (`marquez.ts` `get`, `readBounded`, `paged`); the CLI maps it to exit 1. `check --wait` polls every 2 s, bounded by `--wait` (0 to 600 s). No swallowed errors: the one `catch` without a rethrow in `checkOnce` treats only a 404 namespace as "no jobs" and rethrows everything else. |
| 2 | Writes safe to retry | pass | The emitter only appends events (file transport, `append=True`) or POSTs them; each event carries its run's `runId` and `eventType`, so a retried POST repeats the same event for the same run rather than creating a new run. The demo rewrites its CSV outputs whole on every run. The TypeScript side only reads. |
| 3 | No race conditions | pass | No threads or shared mutable state in either package; the TypeScript CLI awaits each request, and `summary` runs two independent reads in `Promise.all`. |
| 4 | Don't trust the clock | fixed | Event times are UTC (`datetime.now(UTC).isoformat()`, `emitter.py`). Found: `check --wait` computed its deadline from `Date.now()` deltas; now `performance.now()` (injectable as `Io.now`), test `check --wait gives up at the deadline, measured on the injected monotonic clock`. |
| 5 | Read before changing | pass | APIs exist in the pinned versions (openlineage-python 1.54.0, jsonschema 4, TypeScript 7; mypy and tsc strict pass). Environment variables: `OPENLINEAGE_URL` (default target of `lineage-emit demo`) and `MARQUEZ_URL` (CLI and the CI-only test), both in the README; the `DBT_*`/`OPENLINEAGE__*` variables in the Makefile are dbt's and OpenLineage's own. |
| 6 | Never break compatibility | pass | Events are validated against the official OpenLineage 2-0-2 schemas and facet schemas bundled offline (`validate.py`); unknown custom facets are allowed. Parsers of Marquez responses treat optional fields as optional (`optStr`, `optNum`). |
| 7 | One source of truth | pass | The bundled schemas in `python/src/lineage_explorer/schemas` are copies of OpenLineage 1.54.0's (named in `validate.py` and `schemas/NOTICE`), updated together with the `openlineage-python==1.54.0` pin. Marquez is the store; the CLI caches nothing. Versions: Node 24 in CI, `engines`, README; Python 3.11+ in `pyproject.toml` and README, CI 3.12. |
| 8 | Small changes, no secrets, validate input | pass | Secret scan (`grep -rniE "password\|secret\|api_?key\|token"` over `python/src`, `js/src`): no matches. Inputs validated with clear errors: job and dataset names (`_check_name`), declared columns for column lineage, target URLs (`client_for`), event files (line and event caps, JSON objects only), Marquez base URL, search term, depth, `--job` spec and integer options (`cli.ts`). No new dependency. |
| 9 | Tests that can fail | fixed | No tautologies; the one skip has a reason (`needs MARQUEZ_URL`, the CI `marquez` job runs it), and `test_dbt.py` uses `importorskip` with a reason. Mutation table below: 16 of 17 killed before, 17 of 17 after. |
